# Vyom ERP — Complete Backup and Restoration Operational Guide

> **Operational Purpose:** This document provides the end-to-end operational procedure for creating a complete, non-corrupting backup of the Vyom ERP application and safely restoring it. Use this procedure before applying database migrations, schema changes, large refactors, or risky code modifications.

---

## 1. System Architecture & Complete Backup Scope

Vyom ERP's full application state is distributed across three distinct persistence layers. A backup that omits any one of these three layers will produce an incomplete or non-functional recovery state.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        VYOM ERP APPLICATION STATE                      │
├──────────────────────────┬──────────────────────────┬──────────────────┤
│    1. RELATIONAL DATA    │    2. PHYSICAL FILES     │  3. RUNTIME &    │
│       (PostgreSQL)       │       (Disk Blobs)       │  CONFIGURATION   │
├──────────────────────────┼──────────────────────────┼──────────────────┤
│ Database: `erp_db`       │ Directory:               │ Files:           │
│ Container: `vyom-erp-db` │ `server/uploads/`        │ - `.env`         │
│ Volume: `erp_pgdata`     │ (Mounted to /app/uploads)│ - `docker-       │
│ Port: 5433 (Host) /      │                          │   compose.yml`   │
│       5432 (Internal)    │ Contains PDFs, drawings, │ - `nginx.conf`   │
│                          │ BOM spreadsheets, images │                  │
│ 20 relational tables &   │                          │ JWT secret, DB   │
│ sequences                │                          │ credentials, SMTP│
└──────────────────────────┴──────────────────────────┴──────────────────┘
```

### Component Breakdown

#### A. PostgreSQL Database (`erp_db`)
- **Container Name:** `vyom-erp-db`
- **Internal Port:** `5432` | **Host Port:** `5433`
- **PostgreSQL Version:** PostgreSQL 16 (Alpine-based)
- **Default Database:** `erp_db` | **Default Superuser:** `postgres`
- **Named Docker Volume:** `erp_pgdata` (mounted to `/var/lib/postgresql`)
- **Table Inventory (20 Relational Tables):**
  1. `orders`: Root customer purchase orders, target dates, priorities, order statuses, and whole-order PO numbers (`YY(YY+1)XXXX`).
  2. `order_line_items`: Line-item items per order, description, quantities, panel sizes, catalog references.
  3. `order_units`: Discrete panel units, unit serial IDs, assigned departments (`Sales`, `Design`, `Purchase`, etc.), hold statuses, wireman assignments, QC dates, dispatch and invoice dates.
  4. `order_steps`: Order-level workflow milestones (e.g. `Upload PO`).
  5. `unit_steps`: Panel-level granular lifecycle tasks and completion timestamps.
  6. `documents`: Master polymorphic metadata table linking uploaded files to `Order`, `Unit`, or `Step` records. Stores original file names, stored file names, MIME types, file sizes, and uploaders.
  7. `part_number_documents`: Technical drawings and layout sheets linked to catalog part numbers.
  8. `task_masters`: Dynamic workflow task templates across departments.
  9. `column_masters`: Dynamic data column definitions for the master orders table.
  10. `department_column_visibility`: Department- and role-specific column display configurations.
  11. `panel_size_masters`: Standard panel physical dimensions (Height, Width, Depth).
  12. `part_number_masters`: Internal part numbers, catalog codes, and description templates.
  13. `wireman_masters`: Factory floor electrical technicians and wiremen roster.
  14. `system_settings`: System configurations, financial year parameters, and global toggles.
  15. `companies`: Client company and customer records.
  16. `company_locations`: Client delivery addresses and billing sites.
  17. `users`: User authentication accounts, password hashes (`bcryptjs`), and 12 RBAC roles (`Admin`, `Manager`, `Sales`, `Design`, `Purchase`, `Stores`, `Planning`, `Production`, `QC`, `Dispatch`, `Accounts`, `Viewer`).
  18. `vendor_purchase_orders`: Supplier purchase orders generated by the Purchase department.
  19. `vendor_purchase_order_units`: Unit-to-vendor PO allocation lines.
  20. `activity_logs`: Chronological audit trail and timeline of user events.
- **Sequences:** Primary key auto-increment sequences (e.g., `orders_id_seq`, `order_units_id_seq`, `documents_id_seq`).

#### B. Physical Uploaded Documents (`server/uploads/`)
- **Host Path:** `server/uploads/` (e.g., `C:\Users\cerul\Documents\ERP\server\uploads`)
- **Container Path:** `/app/uploads` (mounted from host `./server` inside `vyom-erp-backend`)
- **Contents:** Actual binary files on disk:
  - Customer purchase orders (`.pdf`)
  - Single Line Diagrams (SLDs) and electrical schematics (`.pdf`, `.dwg`, `.png`)
  - Bills of Materials (`.xlsx`, `.csv`)
  - Quality inspection photos, test certificates, and signed delivery challans.
- **The Relational-Physical Invariant:** The database `documents` table stores only *metadata* (`file_name`, `mime_type`, `file_size`). The physical file *must* exist in `server/uploads/`.
  - **Restoring database without uploads:** Results in broken download links (HTTP 404) for all drawings and BOMs.
  - **Restoring uploads without database:** Results in orphaned physical files that the ERP cannot query or display.
  - **Both layers must always be captured and restored together.**

#### C. Application Configuration & Environment Variables
- **Files:**
  - `.env`: Contains production database credentials (`DB_USER`, `DB_PASSWORD`, `DB_NAME`, `DB_PORT`), `JWT_SECRET` (critical for session tokens), and SMTP notification parameters (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`).
  - `docker-compose.yml`: Multi-container port bindings, service definitions, volume mappings, and environment variables.
  - `nginx.conf` & `Dockerfile`: Production web server proxy routing rules.

## 2. Backup Strategy: Running vs. Stopped Containers

| Scenario | Containers Running (Online / Hot) | Containers Stopped (Offline / Cold) |
| :--- | :--- | :--- |
| **Downtime** | **Zero downtime** | Brief maintenance window (containers stopped) |
| **Consistency** | **ACID Transaction Snapshot:** PostgreSQL MVCC guarantees a consistent point-in-time snapshot of all tables as of the dump start time. | **Quiescent Freeze:** All background tasks, SSE events, and client writes are stopped; 100% frozen state. |
| **Best Used For** | Daily automated backups, active development sessions, pre-feature testing. | Major version upgrades, destructive database schema migrations, bare-metal server migrations. |
| **Method** | `pg_dump` executed inside the running container via `docker exec`. | Stop app containers (`vyom-erp-backend`), then dump database or archive `erp_pgdata` volume. |

> [!CAUTION]
> **Windows PowerShell Redirection Guardrail:**
> Never run `docker exec vyom-erp-db pg_dump ... > backup.sql` in Windows PowerShell. PowerShell's standard output redirection (`>`) can alter line endings to CRLF, prepend a UTF-16 Byte Order Mark (BOM), or corrupt custom-format binary dumps.
> **The Safe Standard:** Execute `pg_dump -f /tmp/backup.dump` directly inside the container, copy it out with `docker cp`, and remove the container temp file.

## 3. Step-by-Step Backup Execution Guide

You can specify any destination directory, such as a local backup folder (`C:\Users\cerul\Documents\ERP\backups`), an external hard drive (e.g. `E:\ERP_Backups`), or a network share.

### Option A: Online Hot Backup (Containers Running) — Recommended

#### Windows PowerShell Commands:
```powershell
# 1. Define backup destination and timestamp
$TIMESTAMP = Get-Date -Format "yyyyMMdd_HHmmss"
$BACKUP_DIR = "C:\Users\cerul\Documents\ERP\backups\vyom_backup_$TIMESTAMP"
New-Item -ItemType Directory -Force -Path $BACKUP_DIR | Out-Null
Write-Host "Creating Vyom ERP backup in: $BACKUP_DIR" -ForegroundColor Cyan

# 2. Export PostgreSQL Database (Custom Compressed Binary Format)
Write-Host "Dumping PostgreSQL database (custom binary format)..." -ForegroundColor Yellow
docker exec vyom-erp-db pg_dump -U postgres -d erp_db -F c -b -v -f /tmp/erp_db.dump
docker cp vyom-erp-db:/tmp/erp_db.dump "$BACKUP_DIR\erp_db.dump"
docker exec vyom-erp-db rm -f /tmp/erp_db.dump

# 3. Export PostgreSQL Database (Human-Readable Plain SQL Format with Drop Statements)
Write-Host "Dumping PostgreSQL database (plain SQL format)..." -ForegroundColor Yellow
docker exec vyom-erp-db pg_dump -U postgres -d erp_db --clean --if-exists -f /tmp/erp_db.sql
docker cp vyom-erp-db:/tmp/erp_db.sql "$BACKUP_DIR\erp_db.sql"
docker exec vyom-erp-db rm -f /tmp/erp_db.sql

# 4. Archive Physical Uploads Directory
Write-Host "Archiving server/uploads directory..." -ForegroundColor Yellow
Compress-Archive -Path "server\uploads\*" -DestinationPath "$BACKUP_DIR\uploads.zip" -Force

# 5. Archive Application Configuration & Environment Files
Write-Host "Copying configuration files..." -ForegroundColor Yellow
Copy-Item ".env" "$BACKUP_DIR\.env" -ErrorAction SilentlyContinue
Copy-Item "docker-compose.yml" "$BACKUP_DIR\docker-compose.yml" -ErrorAction SilentlyContinue
Copy-Item "nginx.conf" "$BACKUP_DIR\nginx.conf" -ErrorAction SilentlyContinue

# 6. Verify Backup Artifacts
Write-Host "`nBackup completed successfully! Contents:" -ForegroundColor Green
Get-ChildItem -Path $BACKUP_DIR | Select-Object Name, Length, LastWriteTime | Format-Table -AutoSize
```

#### Linux / macOS / WSL Bash Commands:
```bash
#!/usr/bin/env bash
set -euo pipefail

# 1. Define backup destination and timestamp
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
BACKUP_DIR="./backups/vyom_backup_${TIMESTAMP}"
mkdir -p "${BACKUP_DIR}"
echo "Creating Vyom ERP backup in: ${BACKUP_DIR}"

# 2. Export PostgreSQL Database (Custom Binary & Plain SQL)
docker exec vyom-erp-db pg_dump -U postgres -d erp_db -F c -b -v -f /tmp/erp_db.dump
docker cp vyom-erp-db:/tmp/erp_db.dump "${BACKUP_DIR}/erp_db.dump"
docker exec vyom-erp-db rm -f /tmp/erp_db.dump

docker exec vyom-erp-db pg_dump -U postgres -d erp_db --clean --if-exists -f /tmp/erp_db.sql
docker cp vyom-erp-db:/tmp/erp_db.sql "${BACKUP_DIR}/erp_db.sql"
docker exec vyom-erp-db rm -f /tmp/erp_db.sql

# 3. Archive Physical Uploads
tar -czf "${BACKUP_DIR}/uploads.tar.gz" -C server uploads

# 4. Copy Configuration Files
cp -f .env "${BACKUP_DIR}/.env" 2>/dev/null || true
cp -f docker-compose.yml "${BACKUP_DIR}/docker-compose.yml"
cp -f nginx.conf "${BACKUP_DIR}/nginx.conf" 2>/dev/null || true

# 5. Verify Artifacts
ls -lh "${BACKUP_DIR}"
```

### Option B: Offline Cold Backup (Containers Stopped)

When performing major breaking operations, freeze container state:

#### Windows PowerShell Commands:
```powershell
$TIMESTAMP = Get-Date -Format "yyyyMMdd_HHmmss"
$BACKUP_DIR = "C:\Users\cerul\Documents\ERP\backups\vyom_cold_backup_$TIMESTAMP"
New-Item -ItemType Directory -Force -Path $BACKUP_DIR | Out-Null

# 1. Stop web and backend containers to freeze writes
Write-Host "Stopping application backend and dev server..." -ForegroundColor Yellow
docker stop vyom-erp-backend vyom-erp-dev

# 2. Ensure database container is accessible for quiescent dump
docker start vyom-erp-db

# 3. Dump database without concurrent write risk
docker exec vyom-erp-db pg_dump -U postgres -d erp_db -F c -b -f /tmp/erp_db.dump
docker cp vyom-erp-db:/tmp/erp_db.dump "$BACKUP_DIR\erp_db.dump"
docker exec vyom-erp-db rm -f /tmp/erp_db.dump

# 4. Optional: Archive raw Docker volume erp_pgdata directly
docker run --rm -v erp_pgdata:/volume -v "${BACKUP_DIR}:/backup" alpine tar -czf /backup/pgdata_volume.tar.gz -C /volume .

# 5. Archive uploads and configs
Compress-Archive -Path "server\uploads\*" -DestinationPath "$BACKUP_DIR\uploads.zip" -Force
Copy-Item ".env" "$BACKUP_DIR\.env" -ErrorAction SilentlyContinue
Copy-Item "docker-compose.yml" "$BACKUP_DIR\docker-compose.yml"

# 6. Restart containers
docker start vyom-erp-backend vyom-erp-dev
Write-Host "Cold backup complete!" -ForegroundColor Green
```

## 4. Step-by-Step Restoration and Recovery Guide

Restoring Vyom ERP from a backup requires restoring the database schema/data, extracting the physical uploads into `server/uploads/`, and restarting application containers.

### Prerequisites Before Restoring
1. Identify the backup directory containing `erp_db.dump` (or `erp_db.sql`) and `uploads.zip`.
2. Stop the application backend container (`vyom-erp-backend`) so no open connections lock database tables during the drop/restore phase.

---

### Step 1: Restoring the PostgreSQL Database

#### Windows PowerShell Commands:
```powershell
# Set the path to the backup folder you wish to restore
$RESTORE_DIR = "C:\Users\cerul\Documents\ERP\backups\vyom_backup_YYYYMMDD_HHMMSS"

Write-Host "Restoring database from: $RESTORE_DIR" -ForegroundColor Cyan

# 1. Stop backend container to terminate connection pool locks
Write-Host "Stopping backend to release database connections..." -ForegroundColor Yellow
docker stop vyom-erp-backend -t 5

# 2. Ensure database container is running
docker start vyom-erp-db

# 3. Clean and recreate the target database
Write-Host "Recreating clean erp_db..." -ForegroundColor Yellow
docker exec -i vyom-erp-db psql -U postgres -d postgres -c "DROP DATABASE IF EXISTS erp_db WITH (FORCE);"
docker exec -i vyom-erp-db psql -U postgres -d postgres -c "CREATE DATABASE erp_db;"

# 4. Restore using Custom Binary Dump (pg_restore)
Write-Host "Restoring schema, tables, sequences, and data..." -ForegroundColor Yellow
docker cp "$RESTORE_DIR\erp_db.dump" vyom-erp-db:/tmp/restore_db.dump
docker exec -i vyom-erp-db pg_restore -U postgres -d erp_db -v /tmp/restore_db.dump
docker exec -i vyom-erp-db rm -f /tmp/restore_db.dump

# --- ALTERNATIVE: If restoring from plain SQL dump (erp_db.sql) ---
# docker cp "$RESTORE_DIR\erp_db.sql" vyom-erp-db:/tmp/restore_db.sql
# docker exec -i vyom-erp-db psql -U postgres -d erp_db -f /tmp/restore_db.sql
# docker exec -i vyom-erp-db rm -f /tmp/restore_db.sql
```

#### Linux / macOS / WSL Bash Commands:
```bash
RESTORE_DIR="./backups/vyom_backup_YYYYMMDD_HHMMSS"

# Stop backend container
docker stop vyom-erp-backend -t 5
docker start vyom-erp-db

# Clean and recreate database
docker exec -i vyom-erp-db psql -U postgres -d postgres -c "DROP DATABASE IF EXISTS erp_db WITH (FORCE);"
docker exec -i vyom-erp-db psql -U postgres -d postgres -c "CREATE DATABASE erp_db;"

# Copy and restore
docker cp "${RESTORE_DIR}/erp_db.dump" vyom-erp-db:/tmp/restore_db.dump
docker exec -i vyom-erp-db pg_restore -U postgres -d erp_db -v /tmp/restore_db.dump
docker exec -i vyom-erp-db rm -f /tmp/restore_db.dump
```

---

### Step 2: Restoring Physical Uploaded Documents

Extracting the backup archive restores all drawing PDFs, BOM spreadsheets, and customer PO attachments into `server/uploads/`:

#### Windows PowerShell Commands:
```powershell
Write-Host "Restoring physical uploads to server\uploads..." -ForegroundColor Yellow

# Ensure server\uploads exists
if (-not (Test-Path "server\uploads")) {
    New-Item -ItemType Directory -Force -Path "server\uploads" | Out-Null
}

# Expand the archive (overwriting existing files with backed-up versions)
Expand-Archive -Path "$RESTORE_DIR\uploads.zip" -DestinationPath "server\uploads" -Force
Write-Host "Uploads restored successfully." -ForegroundColor Green
```

#### Linux / macOS / WSL Bash Commands:
```bash
mkdir -p server/uploads
tar -xzf "${RESTORE_DIR}/uploads.tar.gz" -C server/
```

---

### Step 3: Restoring Configuration & Restarting Containers

```powershell
# 1. Restore .env if necessary
if (Test-Path "$RESTORE_DIR\.env") {
    Copy-Item "$RESTORE_DIR\.env" ".env" -Force
}

# 2. Restart backend and frontend services
Write-Host "Restarting Vyom ERP containers..." -ForegroundColor Yellow
docker start vyom-erp-backend vyom-erp-dev

# Wait 3 seconds for Express server and pool initialization
Start-Sleep -Seconds 3
Write-Host "Services restarted." -ForegroundColor Green
```

## 5. Post-Restoration Verification & Health Checklist

To verify that the application has been restored into a fully functional state, execute the following four verification checks:

### Check 1: Container Status & Service Connectivity
Confirm that all three core containers are in an `Up` status:
```powershell
docker ps --filter "name=vyom-erp" --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
```
*Expected Output:*
```text
NAMES              STATUS         PORTS
vyom-erp-dev       Up ...         0.0.0.0:5173->5173/tcp
vyom-erp-backend   Up ...         0.0.0.0:5000->5000/tcp
vyom-erp-db        Up ...         0.0.0.0:5433->5432/tcp
```

### Check 2: Database Record & Entity Counts
Confirm that all core tables and rows are restored and populated:
```powershell
docker exec -i vyom-erp-db psql -U postgres -d erp_db -c "
SELECT 'orders' AS table_name, count(*) AS count FROM orders
UNION ALL
SELECT 'order_units', count(*) FROM order_units
UNION ALL
SELECT 'documents', count(*) FROM documents
UNION ALL
SELECT 'users', count(*) FROM users
UNION ALL
SELECT 'task_masters', count(*) FROM task_masters
ORDER BY table_name;
"
```
*Expected Result:*
- All tables return non-zero counts reflecting your production/development data (e.g., ~121 orders, ~1597 order_units, ~219 documents, 14 users).

### Check 3: Document & Physical File Attachment Integrity
Verify that documents cataloged in the database actually exist as files on disk in `server/uploads/`:
```powershell
# Query sample document filenames and test their physical existence
$SAMPLE_DOC = docker exec -i vyom-erp-db psql -U postgres -d erp_db -t -A -c "SELECT file_name FROM documents WHERE file_name IS NOT NULL LIMIT 1;"
if ($SAMPLE_DOC -and (Test-Path "server\uploads\$SAMPLE_DOC")) {
    Write-Host "Document attachment check PASSED: server\uploads\$SAMPLE_DOC exists on disk." -ForegroundColor Green
} else {
    Write-Host "Document check WARNING: Could not find server\uploads\$SAMPLE_DOC" -ForegroundColor Red
}
```

### Check 4: Backend API Endpoint & Auth Health
Verify that the Express monolith is listening and responding on port 5000:
```powershell
# 1. Unauthenticated health probe (must return HTTP 401 Unauthorized, proving Express and auth middleware are active)
try {
    Invoke-RestMethod -Uri "http://localhost:5000/api/system-settings" -Method Get
} catch {
    if ($_.Exception.Response.StatusCode.value__ -eq 401) {
        Write-Host "API Gateway check PASSED: Server is active and enforcing authentication (HTTP 401)." -ForegroundColor Green
    } else {
        Write-Host "API Check unexpected status: $($_.Exception.Message)" -ForegroundColor Red
    }
}

# 2. Authenticated health probe via test suite
node server/test_po_system.js
```
*Expected Result:*
- `node server/test_po_system.js` runs against `http://localhost:5000` and reports `44 / 44 PASSED`.

## 6. One-Liner Quick Safety Net Commands

Keep these quick commands handy before starting experimental changes:

### Quick Pre-Test Snapshot (PowerShell):
```powershell
$D = "C:\Users\cerul\Documents\ERP\backups\snap_$(Get-Date -Format 'yyyyMMdd_HHmmss')"; New-Item -ItemType Directory -Force -Path $D | Out-Null; docker exec vyom-erp-db pg_dump -U postgres -d erp_db -F c -b -f /tmp/s.dump; docker cp vyom-erp-db:/tmp/s.dump "$D\erp_db.dump"; docker exec vyom-erp-db rm -f /tmp/s.dump; Compress-Archive -Path "server\uploads\*" -DestinationPath "$D\uploads.zip" -Force; Copy-Item ".env" "$D\.env" -ErrorAction SilentlyContinue; Write-Host "Snapshot saved: $D" -ForegroundColor Green
```

### Quick Rollback (PowerShell):
*(Replace `$D` with your snapshot folder path)*
```powershell
$D = "C:\Users\cerul\Documents\ERP\backups\snap_YYYYMMDD_HHMMSS"; docker stop vyom-erp-backend; docker exec -i vyom-erp-db psql -U postgres -d postgres -c "DROP DATABASE IF EXISTS erp_db WITH (FORCE); CREATE DATABASE erp_db;"; docker cp "$D\erp_db.dump" vyom-erp-db:/tmp/r.dump; docker exec -i vyom-erp-db pg_restore -U postgres -d erp_db /tmp/r.dump; docker exec vyom-erp-db rm -f /tmp/r.dump; Expand-Archive -Path "$D\uploads.zip" -DestinationPath "server\uploads" -Force; docker start vyom-erp-backend; Write-Host "Rollback complete!" -ForegroundColor Green
```

## 7. Important Operational Guardrails (From AGENTS.md)

1. **Order Number Immutability:** Historical order numbers (`YY(YY+1)XXXX`) and unit serials are shared on physical customer invoices and panel metal labels. Never run resequencing scripts on restored production databases.
2. **Task Masters Retention:** Database initialization migrations must never invoke `TRUNCATE TABLE task_masters`. The restored database preserves your customized dynamic task templates across all departments.
3. **Mandatory Sales & Design Gate Retention:** The restored database retains the mandatory gates (`hasDrawing && hasBom && designConfirmed` required before units advance from Design to Purchase).
